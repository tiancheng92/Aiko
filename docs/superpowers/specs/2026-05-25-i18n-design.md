# Multi-Language UI Support — Design Spec

**Date**: 2026-05-25
**Status**: Draft

## Overview

Add i18n support to the Aiko desktop pet frontend (Vue 3). Scope is frontend-only — Go backend strings (tool descriptions, error messages, Wails event messages) remain unchanged.

Supported languages: **zh-CN**, **en**, **ja**, **ko**.

## Architecture

```
macOS system language (navigator.language)
        │
        ▼
  main.js bootstrap
        │
        ├─ GetConfig() ──► config.Language has value? ──► use config value
        │                                                   │
        └─ empty (first run) ──► detect system language ────┘
                │
                ▼
        createI18n(locale) ──► app.use(i18n)
                │
                ▼
        all components $t('key') reactive render
                │
        ──────── user switches language ────────
                │
                ▼
    SettingsWindow language selector
        │
        ├─ i18n.locale = newLang            ← instant
        └─ SaveConfig({Language: newLang})   ← persists
```

- Language preference stored in Go config as `Language string` field (SQLite `settings` table)
- Empty string `""` means "follow system"
- `"跟随系统"` option clears the stored preference
- System language not in supported list → fallback to `en`

## Language Detection

File: `frontend/src/locales/index.js`

```js
const SUPPORTED = ['zh-CN', 'en', 'ja', 'ko']
const FALLBACK = 'en'

function detectLocale(configLanguage) {
  if (configLanguage && SUPPORTED.includes(configLanguage)) return configLanguage
  const sys = navigator.language       // e.g. "zh-Hans-CN"
  const short = sys.slice(0, 2)        // "zh"
  return SUPPORTED.find(l => l.startsWith(short)) || FALLBACK
}
```

## Dependencies

Add to `package.json`:
- `vue-i18n` — standard Vue 3 i18n library, Composition API support

```bash
cd frontend && yarn add vue-i18n
```

## File Structure

```
frontend/src/locales/
  index.js         ← createI18n() factory, locale detection
  zh-CN.json       ← Chinese (Simplified)
  en.json          ← English
  ja.json          ← Japanese
  ko.json          ← Korean
```

## Translation Key Convention

Keys segmented by component/domain, dot-separated, max 3 levels deep:

```json
{
  "settings": {
    "title": "设置",
    "tabs": {
      "general": "通用",
      "appearance": "外观",
      "model": "模型"
    }
  },
  "chat": {
    "placeholder": "输入消息...",
    "send": "发送"
  }
}
```

- Top-level key = component or domain (`settings`, `chat`, `toolConfirm`, `notification`)
- All 4 locale files share identical key structure
- No encoding language in key names

## Go Backend Changes

### Config struct (`internal/config/`)

Add one field:

```go
Language string `json:"language"` // "" = follow system
```

### DB migration (`internal/db/`)

```sql
ALTER TABLE settings ADD COLUMN language TEXT DEFAULT '';
```

### Wails bindings

`GetConfig` / `SaveConfig` automatically handle the new field. `wails generate module` regenerates frontend bindings.

## Frontend Changes by Component

### main.js

- Import `createI18n`
- Call `GetConfig()` during bootstrap
- Create i18n instance, `app.use(i18n)`

### SettingsWindow.vue

- Add language selector to "通用" (general) tab, as first row
- Dropdown with: 中文 / English / 日本語 / 한국어 / 跟随系统
- On change: `i18n.locale = newLang` + `SaveConfig({Language: newLang})`
- "跟随系统" sets `Language` to `""`
- tab `label` and all UI strings switched to `$t('settings.xxx')`

### ChatPanel.vue

- Placeholder, tooltip text, status messages → `$t('chat.xxx')`

### ChatBubble.vue

- Button tooltips → `$t('chatBubble.xxx')`

### ToolConfirmModal.vue

- Dialog title, buttons, warning text → `$t('toolConfirm.xxx')`

### NotificationBubble.vue / ExecutionProgress.vue / ContextMenu.vue

- Minimal keys, same pattern

### Components with NO i18n changes

- App.vue, Live2DPet.vue, VRMPet.vue, FloatingBall.vue, CodeRain.vue, LinkPreview.vue
- These contain no user-facing text

## Initial Translation Strategy

- Machine-translate all 4 locale files for the initial implementation
- Translation quality marked as "rough draft" — user polishes later
- Key structure is the source of truth; translations can be corrected file by file without code changes

## Out of Scope

- Go backend string i18n (tool descriptions, error messages, Wails event names)
- Pluralization / number formatting / date formatting (can add when needed)
- RTL language support
- Dynamic locale loading (all 4 files are small enough to bundle)
